# Etapa 0.11: servicio HTTPS de desarrollo (solo lectura)

Código en neon/server. El adaptador valida el JWT de Neon Auth con jose, fija el emisor y algoritmo, y consulta PostgreSQL con pg. No acepta identidad de parámetros del usuario. El rol faro_api y el contexto de identidad se configuran dentro de una transacción de solo lectura. El cliente no recibe credenciales. Se devuelve 403 si la cuenta no está habilitada. No se habilita CORS para ningún dominio. Solo permite consultas de cuenta, espacios, marcas y borradores. No crea usuarios, no permite escrituras ni llama a redes. El ejecutable falla fuera de la rama dev-saas.

Compilación por GitHub Actions (artefacto ZIP y lockfile generado). La instalación de dependencias en el entorno de conversación falló por DNS. Revisar, fijar y versionar el lockfile generado antes de una entrega reproducible; las versiones directas están fijadas. Validar el bundle en Neon, comprobar salud y rechazos HTTP, verificar JWT con una sesión real, verificar audiencia y revocación/sesión vigente, y pruebas de integración antes de abrir acceso. El frontend se conserva sin cambios en modo demo; no hay autenticación real desde GitHub Pages. No se configura un servicio de pago.
